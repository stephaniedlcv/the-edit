1. Crear componente:
`src/components/chroma-spine.tsx`

Debe exportar:
- `ChromaSpine`

2. Props requeridas:
- `entries`
- `activeFamily?`
- `onSelect?`
- `hrefBase?`
- `showCounts?`
- `size?`: `"sm" | "md" | "lg"`
- `orientation?`: `"horizontal" | "vertical"` si no complica; si complica, empezar solo horizontal.
- `ariaLabel?`
- `className?`

3. Shape de `entries`:
Usar el tipo `SpectrumEntry` de `src/lib/wardrobe/spectrum.ts` si ya existe.
Cada entry debe tener:
- family
- meta
- count
- pieces? opcional

4. Orden:
Debe renderizar usando `sortFamiliesBySpectralOrder()` de `spectrum.ts`.
No ordenar por count para la espina principal.
El count solo debe afectar la altura/ancho/intensidad visual de la barra.

5. Visual:
ChromaSpine debe ser una tira editorial de barras/píldoras cromáticas.
Debe usar:
- `meta.hex`
- `meta.borderHex` para cream/white si existe
- `meta.kind`

Tratamientos:
- `kind: "hue"` → barra sólida con background `meta.hex`.
- `kind: "special"`:
  - multicolor → tratamiento simple honesto, por ejemplo mini-gradient CSS inline o striped subtle.
  - metallic → tratamiento simple honesto, por ejemplo linear-gradient cálido metálico.
  - statement → outline/emphasis treatment.
No fingir que special es un hue normal.
- `unknown` → fallback greige con borde visible.

6. Counts:
- `count` debe escalar tamaño de barra de forma suave.
- Evitar que una familia con count muy alto destruya el layout.
- Usar escala min/max clamp.
- Si count = 0 y aparece, renderizar muy pequeño o con opacity baja; pero por defecto la data estática puede omitir count 0.
- Mostrar número solo si `showCounts` es true.

7. Interacción:
Si `hrefBase` existe, cada segmento debe ser un `Link` a:
`{hrefBase}?colorFamily={family}`

Si `onSelect` existe y no hay hrefBase, cada segmento debe ser un `button`.

Si no hay `hrefBase` ni `onSelect`, cada segmento debe ser un `div`/`span` no interactivo.

Debe tener:
- aria-label por segmento: familia + count.
- focus visible cuando sea interactivo.
- active state si `activeFamily` coincide.
- title opcional para hover.

8. Accesibilidad:
- `aria-label` general para el componente.
- cada segmento interactivo debe tener label.
- no depender solo del color: si showCounts está activo, mostrar count; si no, usar title/aria.
- focus ring visible.
- respetar prefers-reduced-motion; no hacer animaciones grandes.

9. Responsive:
Debe funcionar desde 360px.
No debe romper layout.
En horizontal puede permitir overflow-x suave si hace falta.
Debe ser usable en mobile.
