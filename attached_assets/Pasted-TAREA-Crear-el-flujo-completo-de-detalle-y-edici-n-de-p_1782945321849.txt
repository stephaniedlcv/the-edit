TAREA: Crear el flujo completo de detalle y edición de piezas para el módulo Closet de THE EDIT.

Contexto:
Estamos trabajando en THE EDIT / Closet OS, branch ui/blush-glass-foundation.
Ya existe:
- /closet = Closet Dashboard
- /closet/gallery = Closet Gallery limpia e interactiva
- getWardrobeItems()
- tipos WardrobeItem y WardrobeCategory
- componentes existentes como closet-card, closet-item-edit-form, closet-category-board, etc.
- estética Warm Blush / Editorial Glass.

Objetivo:
Crear un flujo premium y funcional para ver y editar cada pieza del closet sin romper el diseño actual.

Rutas deseadas:
1. /closet/gallery
   - Las cards deben navegar al detalle real de la pieza.
   - Actualmente pueden apuntar a /closet/gallery o no tener detalle.
   - Cambiar para que cada card navegue a /closet/item/[id] o /closet/[id], según convenga con la estructura del app.

2. Nueva ruta de detalle:
   /closet/item/[id] o /closet/[id]
   Elegir una opción clara y consistente. Preferencia: /closet/item/[id] para evitar conflicto con /closet/gallery.

Pantalla de detalle:
Debe ser premium, limpia y consistente con Home / Closet Dashboard / Closet Gallery.

Debe incluir:
- Header / hero de pieza:
  - imagen grande de la pieza
  - categoría
  - score promedio
  - nombre
  - color name
  - size
  - status
  - tags o styling tags si existen

- Sección “Style notes”:
  - stylist note si existe
  - outfit pairing ideas si existen
  - no hacer la card gigante; debe verse organizada

- Sección “Scores”:
  Mostrar Love / Versatility / Fit / Capsule como chips o mini cards, no como formulario pesado.

- Sección “Details”:
  source / brand / price / purchase date / product link si existen.
  Todo en layout compacto y premium.
  Product link debe ser botón/pill, no texto largo.

- Actions:
  - Edit piece
  - Back to Gallery
  - Build outfit with this piece si es simple enlazar a /outfits
  - Archive/Delete solo si ya existe lógica segura. Si no existe, no inventar delete destructivo.

Editar pieza:
Revisar si existe componente closet-item-edit-form.tsx.
Si ya existe:
- Reutilizarlo en una ruta o modal de edición.
- No reescribir toda la lógica si ya funciona.
- Darle estilos consistentes si se ve viejo.
- Evitar romper la lógica de guardar.

Si no existe flujo:
- Crear /closet/item/[id]/edit
- Usar datos existentes.
- Mantener campos necesarios:
  name
  category
  type
  color family
  color name
  size
  status
  brand/source
  price
  purchase date
  notes
  scores si ya existen en el tipo

Importante:
No cambiar la forma de los datos salvo que sea necesario.
No romper APIs existentes:
- /api/closet/items
- /api/closet/items/[id]
- /api/closet/items/[id]/image

No tocar:
- Home
- Planner
- Wishlist
- Outfits
- Navigation
excepto si es estrictamente necesario para enlazar.

Estética:
Seguir el patrón actual:
- serif editorial para títulos y nombres de piezas
- sans para body text, labels, buttons, forms
- blush/cream/glass cards
- burgundy accents
- cards redondeadas
- layout tablet/web premium
- responsive mobile

NO hacer:
- No convertir la pantalla en una tabla.
- No mostrar todo como formulario gigante.
- No meter metadata larga en Gallery.
- No romper /closet ni /closet/gallery.
- No hacer commit automáticamente.

Componentes sugeridos:
Crear si ayuda:
- ClosetItemDetailPage
- ClosetItemHero
- ClosetItemScoreGrid
- ClosetItemDetails
- ClosetItemActions
- ClosetItemEditPage
- ClosetDetailCard

Criterios de aceptación:
1. Desde /closet/gallery, click en una card abre el detalle correcto de esa pieza.
2. El detalle muestra imagen, nombre, categoría, color, size, score y notas de forma premium.
3. No se pierde la estética actual.
4. Existe forma clara de volver a Gallery.
5. Existe botón Edit piece.
6. Si se implementa edición, typecheck y build pasan.
7. /closet sigue funcionando.
8. /closet/gallery sigue funcionando.
9. No se reutiliza una card vieja gigante como detalle sin adaptar.
10. No hay metadata larga dentro de Gallery.

Verificación obligatoria:
Correr:

npm run typecheck
npm run build

También correr:

find src/app/closet -maxdepth 5 -type f -print | sort

Y entregar:
1. Archivos modificados.
2. Nuevas rutas creadas.
3. Componentes nuevos creados.
4. Qué lógica existente reutilizó.
5. Resultado de typecheck.
6. Resultado de build.
7. Cómo probar manualmente:
   - abrir /closet/gallery
   - click en una pieza
   - revisar detalle
   - volver a gallery
   - probar Edit piece si se creó
8. No hacer commit. Dejar cambios listos para revisión.
